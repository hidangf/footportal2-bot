# ФУТПОРТАЛ 2: ChatGPT Plus → GitHub → Telegram

Этот вариант **не использует OpenAI API**. Регулярная задача ChatGPT должна создавать новые JSON-посты в папке `queue/`; после создания нового файла GitHub Actions запустит `deliver.py` и опубликует пост в [@footportal2](https://t.me/footportal2).

## Что уже подключено
- Канал: `@footportal2`
- Секрет GitHub Actions: `TELEGRAM_BOT_TOKEN` (создаётся пользователем)
- Workflow: `.github/workflows/deliver.yml`
- Исполнитель: `deliver.py` на стандартной библиотеке Python
- Защита от повторов: `data/sent.json` (для обычных новостей по ссылке, для комментариев по паре персонаж + ссылка)
- Очередь новостей: `queue/имя-файла.json`

**`OPENAI_API_KEY` не нужен.** Старый `footportal.py` сохраняется для справки, но новый workflow его не использует.

## Тест без публикации
В GitHub: Actions → **Footportal2 Telegram delivery** → Run workflow → `dry_run=true`. Это проверка без отправки. Пока нет JSON-файлов в очереди, отправлять нечего.

## Тест публикации
Сначала убедитесь, что бот является администратором канала и описание канала содержит указание на вымышленные юмористические новости. Создайте файл `queue/20261112-120000-01.json` по образцу из `queue/README.md`. Новый файл в main автоматически запустит отправку. Для обычных новостей ссылка на исходную статью публикуется только один раз; отдельные комментарии персонажей могут ссылаться на уже использованный источник, поскольку учитываются отдельно по персонажу и ссылке.

## Важно
Запланированные задачи ChatGPT могут потребовать подтверждения операций в GitHub либо не иметь доступа к нужному инструменту при фоновом запуске. Если это происходит, не будет автоматической доставки. Для проверки следите за первыми запусками задачи ChatGPT и GitHub Actions. Полностью автономная работа через Plus не гарантирована до реального успешного запуска.

В GitHub Settings → Actions → General → Workflow permissions необходимо разрешить **Read and write permissions** для сохранения истории. В настройках канала укажите, что все публикации — художественная пародия и ссылки не подтверждают факты.

Для локального теста: `python deliver.py --dry-run`.

## Дополнительные комментарии персонажей
Основные 1–3 новости за запуск сохраняются; сверх них задача может публиковать отдельные микростатьи с комментариями Ивана Вяткина или Никиты Филатова. Рабочие профили: `lore/characters.json`, редакционные требования: `lore/README.md`, примеры полей для очереди: `queue/README.md`. Комментарии не обязательны в каждом запуске. Они могут относиться к проверенным реальным новостям или опубликованной альтернативной спортивной истории канала. Новых материалов из личных переписок в публичный репозиторий добавлять нельзя.
