# Лор «ФУТПОРТАЛА 2»: правила непрерывности

Это **фиктивная вселенная** для пародийного Telegram-канала @footportal2. Её логика отличается от реального спорта. Она не должна превращаться в заранее написанный сериал.

## Перед КАЖДЫМ запуском
1. Прочитать `references/footportal-original-style.md` (оригинальная манера).
2. Прочитать `lore/world-state.json` и `lore/characters.json`.
3. Сверить `data/sent.json` и последние `queue/*.json`. **Только уже опубликованные** JSON-посты из `sent_files` становятся каноном. Новые ещё не отправленные материалы — лишь заготовки.
4. Искать свежие реальные источники; не повторять URL.

## Правило 70/30
- Ориентир на длинной дистанции: **около 70% самостоятельных новостей, 30% сюжетных продолжений или незаметных отсылок**. Не квотировать каждый пакет механически; бывают полностью независимые выпуски.
- Должно развиваться много **параллельных**, не обязательно пересекающихся линий; по мере публикаций заводить новые (первые месяцы ориентир 5–10 активных/спящих линий).
- Новая самостоятельная новость может впоследствии стать началом линии. НИКОГДА не объявлять о начале «арки», «лоре», «каноне» или «повороте сюжета» в самом канале.
- Исходные статьи из сегодняшнего Sport.ru/Sports.ru используются только как толчок; посты не должны быть преимущественно правдивыми.

## Продолжение = последствия, а не повторение
- Если опубликованы стартовые составы на матч, через подходящий промежуток можно выдать результат **именно этого матча**, преимущественно с уже названными спортсменами (но допускаются обычные нейросетевые подмены).
- Если футболист забил дважды, это может позже стать «серией результативных матчей», затем — трансферным интересом, позицией в таблице лучших бомбардиров; не перескакивай сразу на 30 голов.
- Если игрок «перешёл», запомни клуб и дату; позднее клуб может поменяться только в результате нового события или слегка нейросетевого сбоя.
- Продолжения должны содержать **узнаваемое следствие** одного-двух прежних фактов; не просто одинаковое имя.
- Не выводи старые сюжетные линии в каждом выпуске: делай паузы, периодически возвращайся к давно забытым подробностям.
- Иногда две линии могут неожиданно пересечься, если это выглядит как ошибка нейросети, а не авторская сюжетная кульминация.
- Не делай все новости продолжениями. Полноценный, на первый взгляд бессвязный оригинальный «ФУТПОРТАЛ» — основа ленты.

## Нарастание к концу сезона
- **Ноябрь–январь**: отдельные сбои, разные чемпионаты/эпохи, странные голы, подменённые карьеры. Большинство новостей не связано.
- **Февраль–апрель**: ранее опубликованные ошибки перестают быть единичными и влияют на таблицы, тренерские должности, трансферы, итоги матчей; время от времени скрещиваются две линии.
- **Май–июнь**: накопленные нелепости чаще ведут к новым следствиям, иногда к невозможным положениям в таблицах и турнирах. **Не повышать абсурд путём нарочитого юмора в каждой фразе**, продолжать писать сухие короткие заметки.
- Это тенденция, не строгий календарь: если первая ошибка случилась в мае, она не обязана иметь год предыстории.

## Обновление памяти
- После успешного создания файлов `queue/YYYYMMDD-HHMMSS-XX.json` в main сверить отправку (возможно, она ещё не завершилась). **Не считать неотправленный файл опубликованным фактом**.
- Если отправка подтверждена записью в `data/sent.json`, обновить `lore/world-state.json` через GitHub, сохранив прежние линии. Использовать актуальный blob SHA `fetch_file` → `update_file`, чтобы не перетирать параллельную запись.
- Для новых постов, отправка которых ещё не подтверждена, можно записать черновые кандидаты отдельно в `pending` с `status: "queued"`, но в `arcs[].established_facts` добавлять их только после подтверждения отправки. Следующий запуск должен сверить и обработать новые отправленные публикации.
- Добавить очередной `queue`-путь в `source_posts` у соответствующей арки; для новых направлений придумать короткий уникальный `id`. При отсутствии новой связи состояние можно не менять.
- Не переписывать задним числом опубликованные события. Можно сохранять их противоречия и дополнять новыми — это часть юмора.
- Если не удалось прочитать или записать лор, **не заявлять**, что память обновлена; по возможности читать прошлые посты как резервный источник.

## Будущие персонажи
- `lore/characters.json` пока пуст. Пользователь позже пришлёт сведения о персонажах и переписки реальных прототипов.
- **Не изобретай их заранее**, не путай с разовыми выдуманными игроками из постов.
- После согласования с пользователем сюда добавляются только вымышленные, обезличенные персонажи: публичная роль, характер речи, особенности, знакомства, допустимые сюжетные функции. **Не загружать в публичный GitHub исходные личные переписки или идентифицирующие сведения** без отдельного явного разрешения.
- Позволяй им постепенно появляться в независимых новостях и линиях без нарочитого знакомства с читателем.

## Устройство публикации
Создание `queue/*.json` включает GitHub Actions для отправки в Telegram. Изменение файлов внутри `lore/` **не запускает** отправку. Не менять `deliver.py` для лора и не использовать старый OpenAI API-скрипт.
